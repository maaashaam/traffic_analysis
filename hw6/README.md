# Классификация уровня IT-разработчика (junior / middle / senior) по резюме hh.ru

Автоматическое определение уровня IT-разработчика (**junior / middle / senior**) по данным резюме с hh.ru.

---

## Что делает проект

1. Загружает `hh.csv`.
2. Отбирает резюме IT-разработчиков по ключевым словам в должности/тексте.
3. Формирует целевую переменную `y` (junior/middle/senior) эвристически по названию должности и опыту.
4. Строит график баланса классов.
5. Обучает классификатор по признакам резюме (зарплата, город, возраст, опыт и текст `title+skills`).
6. Печатает `classification report` и `confusion matrix`.

---

## Данные и разметка

### Баланс классов (после фильтров)
```
junior    1272
middle    1086
senior    5171
Dataset size: (7529, 7)
Empty text: 0
```

### Как формируется `y`
Разметка уровня выполняется эвристикой:
- по ключевым словам в названии должности (например, junior/senior/lead/ведущий),
- если по названию не ясно — по опыту (в месяцах), где малый опыт → junior, большой → senior, иначе middle.

---

## Признаки и модель

Используемые признаки:
- числовые: `salary_rub`, `age`, `gender`, `exp_months`
- категориальные: `city` (one-hot)
- текст: `text = title + skills` (TF-IDF с n-граммами)

Модель: `LinearSVC(class_weight="balanced")` в sklearn-пайплайне.

## Выводы

Эксперимент подтверждает, что задача жизнеспособна: модель уверенно отличает уровни разработчика по данным резюме и даёт хорошее качество на тесте (accuracy 0.888, macro-F1 0.791). Класс `senior` распознаётся лучше всего (F1 0.978), а основные ошибки приходятся на границу `junior`–`middle`, что ожидаемо из-за размытых критериев уровня и шумной эвристической разметки целевой переменной. Улучшить качество можно за счёт более чистой разметки (ручная разметка части данных), более строгих правил выделения IT-резюме и более богатой обработки текста навыков и технологий.
